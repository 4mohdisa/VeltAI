# 07 · Notifications & Push

Veltai sends push notifications to drive behaviour: remind, alert, celebrate. Each one must earn its delivery — spam erodes trust faster than anything.

---

## Notification types

| Type | When | Example |
| --- | --- | --- |
| `gym_reminder` | 1h before recommended_gym_time | "Gym in 1 hour. You said 18:00 works best." |
| `meal_reminder` | At meal_schedule time | "Lunch time. Target 600 kcal, 40g protein." |
| `sleep_reminder` | 30min before recommended_bedtime | "Wind down for sleep. Target bedtime 22:30." |
| `streak_at_risk` | 4h before midnight UTC if no session | "Your 13-day streak ends in 4 hours." |
| `lockout_active` | When enforcement window starts and no session | "Apps now locked until you log today's gym." |
| `lockout_lifted` | When session logged during enforcement window | "Lockout lifted. Nice work." |
| `milestone_close` | 2 days before 7/30/100-day streak | "2 more days until your 30-day streak (+200 XP)." |
| `milestone_hit` | When milestone reached | "30-day streak unlocked. +200 XP. Streak freeze earned." |
| `weekly_digest` | Monday 09:00 local | "Your week: 4 gym sessions, hit protein 5/7 days." |
| `ai_nudge` | Contextual, from ai_nudge_log generation | "Sleep was 5.8h average this week. Want to shift bedtime?" |
| `rank_up` | When user crosses rank threshold | "Rank up: Locked In. Streak freeze token earned." |

## Channels

- **APNs** for iOS push (primary)
- **In-app banner** for messages received while app is open
- **Lock screen widget** (Phase 2) for streak and gym status

## Scheduling architecture

### Time-based notifications (reminders)

Generated when AI plan is created — inserted into `scheduled_notifications` with `scheduled_for` timestamp.

Go background worker polls every minute:

```sql
SELECT * FROM scheduled_notifications
WHERE status = 'pending' AND scheduled_for <= NOW()
FOR UPDATE SKIP LOCKED
LIMIT 100;
```

For each, sends APNs push → marks status = 'sent' or 'failed'.

### Event-based notifications

Fired immediately when an event occurs:

- Gym session logged → send `lockout_lifted` if applicable
- Streak milestone hit → send `milestone_hit`
- Rank crossed → send `rank_up`

Go handler sends APNs directly, then logs to `scheduled_notifications` with `status = 'sent'` for audit.

### AI nudges

Generated by separate cron at quiet times:

- Daily nudge generator runs at 11:00 local for each user
- Reads `user_habit_patterns`, `user_food_patterns`, `user_health_correlations`, recent `ai_nudge_log` entries
- Decides if a nudge is warranted based on:
    - User has data pattern worth surfacing
    - Hasn't received same `nudge_type` in last 7 days
    - Today's notification count < `max_notifications_per_day`
    - Not in quiet hours
- If warranted, calls Gemini to generate the nudge text (within style guide: short, kind, specific, no emojis)
- Inserts into `ai_nudge_log` and `scheduled_notifications`

## Rate limiting

### Per-user daily cap

- `notification_preferences.max_notifications_per_day` default = 6
- `notifications_sent_today` increments on each send
- Resets at midnight local
- If cap hit, low-priority notifications are dropped, high-priority (streak_at_risk, lockout_active) still send

### Anti-repetition

- Same `nudge_type` not sent twice in 7 days
- Same scheduled type (e.g. `gym_reminder`) sent at most once per day
- After 3 dismissals of same type, switch to different angle or pause for 14 days

---

## Quiet hours

- Default: 22:00–07:00 local time
- During quiet hours, notifications get scheduled for `quiet_hours_end`
- Exception: `streak_at_risk` overrides quiet hours (it's the user's explicit goal)

## Notification copy guidelines

Write copy that:

- Is **specific** ("your 13-day streak" not "your streak")
- Avoids **shame** ("streak ends in 4 hours" not "you're failing")
- States **the action** ("Log it now" not "Don't forget")
- Is **short** (push notification truncates fast on iOS)
- Uses **no emojis** (matches Isa's writing style; emojis read as gimmicky for a paid health app)
- Uses **no em dashes, no semicolons, no banned filler words** (matches established style guide)

Good: "Gym in 1 hour. 18:00 is your time."

Bad: "Hey there! 💪 Don't forget about your gym session today! You got this! 🙌"

## Edge cases

| Case | Handling |
| --- | --- |
| APNs token expired / device unregistered | Mark as failed, prompt re-register on next app open |
| User disabled push system-wide | All push attempts marked failed silently. In-app banners still work. |
| User dismisses 3 of same notification type | Pause that type for 14 days, suggest related but different angle |
| User changes timezone | Reschedule pending notifications for new local time |
| App in foreground when notification arrives | Show in-app banner instead, suppress push |
| User uninstalls app | APNs returns Unregistered error → mark user.deleted_at, stop all future sends |
| Notification scheduled for the past (clock drift) | Send immediately, don't skip |
| User has same scheduled notification queued multiple times (rare bug) | Worker uses `FOR UPDATE SKIP LOCKED` to prevent duplicates; idempotency token on APNs payload |

## Success metrics

- Notification delivery success rate > 99%
- Open rate (user tapped notification) > 25%
- Dismiss rate (user swiped away without acting) < 40%
- User-disabled-notification rate < 8% after 14 days
- Gym session log rate within 90min of `gym_reminder` > 40%
