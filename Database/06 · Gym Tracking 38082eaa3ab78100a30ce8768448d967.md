# 06 · Gym Tracking

The single habit type for MVP: **going to the gym.**

---

## `gym_habit` — the user's gym commitment

Singleton per user. Stores the user's overall gym intent and configuration.

```sql
CREATE TABLE gym_habit (
  id                          UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  user_id                     UUID NOT NULL UNIQUE REFERENCES users(id) ON DELETE CASCADE,

  is_active                   BOOLEAN NOT NULL DEFAULT TRUE,
  target_sessions_per_week    INT NOT NULL DEFAULT 3,
  preferred_days              TEXT[] DEFAULT '{}',  -- mon, tue, etc.
  preferred_time              TIME,                  -- e.g. 18:00
  training_type               TEXT,                  -- strength | cardio | both | sports_specific
  experience_level            TEXT,                  -- beginner | intermediate | advanced
  gym_location                TEXT,                  -- home | gym | both

  -- For Phase 2 GPS check-in
  gym_lat                     NUMERIC(10,7),
  gym_lng                     NUMERIC(10,7),
  gym_name                    TEXT,

  -- Streak data is computed live from gym_sessions, not stored as counter

  created_at                  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at                  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

ALTER TABLE gym_habit ENABLE ROW LEVEL SECURITY;
CREATE POLICY "gym_habit_own" ON gym_habit
  USING (user_id = (SELECT id FROM users WHERE clerk_id = auth.uid()::TEXT));
```

## `gym_sessions` — the integrity-critical table

One row per (user, day). The unique constraint here makes the LOCKED XP-farming exploit impossible.

```sql
CREATE TABLE gym_sessions (
  id                  UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  user_id             UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,

  session_date        DATE NOT NULL,                -- UTC date
  logged_at           TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  duration_minutes    INT,                          -- optional, user-provided

  verification_source TEXT NOT NULL DEFAULT 'manual',
    -- manual | healthkit_workout | gps_checkin | manual_then_verified
  healthkit_workout_id TEXT,                        -- if verified via HealthKit
  verified_at         TIMESTAMPTZ,                  -- when verification succeeded

  workout_notes       TEXT,                         -- optional free text
  energy_level        INT,                          -- 1-5 user rating
  perceived_effort    INT,                          -- 1-10 RPE

  xp_awarded          INT NOT NULL DEFAULT 25,

  created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),

  -- The single most important constraint: one session per day per user
  CONSTRAINT uq_session_per_day UNIQUE (user_id, session_date)
);

CREATE INDEX idx_gym_sessions_user_date ON gym_sessions(user_id, session_date DESC);

ALTER TABLE gym_sessions ENABLE ROW LEVEL SECURITY;
CREATE POLICY "gym_sessions_own" ON gym_sessions
  USING (user_id = (SELECT id FROM users WHERE clerk_id = auth.uid()::TEXT));
```

## `gym_streak_freezes` — protect rest days

User can apply a freeze to a date to prevent that day from breaking their streak.

```sql
CREATE TABLE gym_streak_freezes (
  id            UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  user_id       UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  frozen_date   DATE NOT NULL,
  applied_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  reason        TEXT,                       -- rest_day | injured | sick | travel | other
  created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),

  CONSTRAINT uq_freeze_per_day UNIQUE (user_id, frozen_date)
);

ALTER TABLE gym_streak_freezes ENABLE ROW LEVEL SECURITY;
CREATE POLICY "freezes_own" ON gym_streak_freezes
  USING (user_id = (SELECT id FROM users WHERE clerk_id = auth.uid()::TEXT));
```

## Streak calculation function

```sql
CREATE OR REPLACE FUNCTION get_gym_streak(p_user_id UUID)
RETURNS INT AS $$
DECLARE
  streak INT := 0;
  check_date DATE := CURRENT_DATE;
  has_activity BOOLEAN;
BEGIN
  LOOP
    SELECT EXISTS (
      SELECT 1 FROM gym_sessions
      WHERE user_id = p_user_id AND session_date = check_date
      UNION ALL
      SELECT 1 FROM gym_streak_freezes
      WHERE user_id = p_user_id AND frozen_date = check_date
    ) INTO has_activity;

    EXIT WHEN NOT has_activity;

    streak := streak + 1;
    check_date := check_date - INTERVAL '1 day';
  END LOOP;

  RETURN streak;
END;
$$ LANGUAGE plpgsql STABLE;
```

## XP integration

When a gym session is logged, the Go endpoint:

1. Inserts into `gym_sessions` with `ON CONFLICT DO NOTHING`
2. If row was inserted (not conflict), calls `AwardXP(user_id, 'gym_session', session_id, 25)`
3. Checks if this completes a 7/30/100-day streak — if so, awards milestone XP
4. If HealthKit verification succeeded, awards +5 XP via `AwardXP(user_id, 'healthkit_verify', session_id, 5)`
